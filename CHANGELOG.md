# Changelog

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Версионирование: пока не выпущено ни одной версии продукта; разделы датируются.

## [Unreleased]

### Added

- Раннер `tools/check.py` — одна команда локальной проверки: целостность
  JSON/CSV, `ruff check`, `ruff format --check`, `pytest`, перегенерация
  индекса спецификаций + `git diff`-гейт, валидаторы `ALWAYS`/`STAGE-00`,
  селектор с ожидаемым кодом блокировки. Флаги `--quick`, `--skip-info`, `--json`.
- 14 тестов на раннер (`tools/tests/test_check.py`); всего 71 тест.
- Три проверки целостности runbook'а в `ALWAYS`: карточка на каждый этап
  реестра с обязательными разделами, скилл на каждый этап с совпадающим
  `name`, декларация проверок на каждый этап. Первый прогон сразу нашёл
  отсутствующий раздел `## Outputs` в карточке STAGE-07.
- Проверка `markdown_links_resolve`: относительные ссылки в документации
  проекта должны указывать на существующие файлы; бейджи вида
  `[![alt](img)](target)` и якоря учитываются.
- CI вызывает ту же команду (`python tools/check.py --skip-info`), поэтому
  локальная и облачная проверки не могут разъезжаться.

### Changed

- `docs/ops/RUNBOOK.md` — раздел про инструменты проверки описывает единый
  раннер как источник истины «зелёного».

### Removed

- BUSL/Business Source License из репозитория: `LICENSES/`, `LICENSE-MAP.md`,
  DCO-требование. `ADR-0002` переведён в `REJECTED` (решение владельца,
  2026-11-16). Лицензия — единая MIT.

## [2026-11-16] — публикация и аудит

### Added

- Импорт архива спецификаций (109 файлов) как read-only источника истины
  с sha256-индексом.
- Runbook: 23 карточки этапов, 24 скилла, 24 декларации проверок,
  реестр и журнал исполнения.
- Инструменты: валидатор артефактов, механический селектор задач, генератор
  индекса спецификаций, установщик скиллов.
- Артефакты `STAGE-00`: карта архитектуры, карта зависимостей, `P0_SCOPE`,
  реестр рисков, глоссарий, `ADR-0001`.
- Двуязычный README (EN/RU), `CONTRIBUTING`, `SECURITY`, `CODE_OF_CONDUCT`,
  CI, шаблоны issue и PR.

### Fixed

- Парсер статуса гейта принимал шаблонную строку
  `STATUS: PASS | CONDITIONAL_PASS | FAIL` за реальный `PASS`.
- Генератор индекса писал CRLF на Windows, из-за чего вывод зависел от ОС.
- Валидатор кэшировал строки индекса без инвалидации и возвращал устаревшие
  данные после перегенерации.
