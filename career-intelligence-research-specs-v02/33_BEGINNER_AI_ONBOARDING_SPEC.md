# Beginner AI Onboarding Specification

## Product promise
Человек, который никогда не использовал AI, должен получить первый безопасный полезный результат без необходимости изучать терминологию, писать сложные промпты или выбирать из десятков сервисов.

## Onboarding principles
- Start with the user's job and a real task.
- Explain jargon only when needed, in plain language.
- One step per screen; progressive disclosure.
- Demonstrate first, then let the user try.
- Never require account creation before explaining why it is needed.
- Always provide a non-AI/manual alternative.
- Do not shame users for low digital literacy.
- Default to the safest low-friction tool available in their region and language.

## Beginner journey
1. What do you do? Capture profession, role, daily tasks and context.
2. What is frustrating or repetitive? Identify one task.
3. Show a concrete before/after example using synthetic or user-approved data.
4. Explain what AI did and what it cannot know.
5. Let the user try with guided input.
6. Teach the user to verify the output.
7. Save the result as a reusable template.
8. Offer the next small workflow only after success.

## Three onboarding modes
- Explore: no account or integration required; sandbox and synthetic examples.
- Guided: user connects an approved tool and follows a wizard.
- Done for me: setup service or partner completes configuration with explicit permissions.

## First success metric
First useful task completed and checked by the user, not course completion or number of prompts sent.

## Accessibility
Support voice input, mobile-first flows, large readable instructions, low-bandwidth mode, plain language, multilingual glossary and downloadable/printable steps.

## Safety
Use fake/demo data by default. Before file upload or account connection, explain what data is shared and with whom. Ask for explicit consent for every external connection and consequential action.

## Acceptance criteria
A novice can complete a profession-relevant first task, understand how to check it and know what to do if the result is wrong.
