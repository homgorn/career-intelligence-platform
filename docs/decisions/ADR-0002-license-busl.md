# ADR-0002 — BUSL для движка, MIT для исполнительного слоя

## Контекст

Репозиторий опубликован под MIT (коммита `10bcc2d`, 229 файлов). Это было
нужно для быстрой проверки инструментов и контента, и это публично.
`docs/architecture/MONETIZATION_STRATEGY.md` предлагает монетизацию
**исполнением** (API, engines, recipes), а не документом. Владелец выбрал
путь BUSL.

Проблема: BUSL (Business Source License 1.1) не работает «сзади». Он
применяется только к версиям, которые выпустите под ним позже. MIT-история
остаётся вечной. Поэтому решение — не «сменить LICENSE задним числом», а
**зафиксировать двухлицензионную модель и границу открытости**.

Спеки, процесс исполнения, валидаторы и скиллы — это наш главный актив и
найденная нами честная публичная позиция: они останутся открытыми.
Движок рекомендаций и исполнение — продукт, и он защищается.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Цена |
| --- | --- | --- | --- |
| A. Оставить MIT на всё | просто, максимально открыто | конкурирующие hosted-сервисы безвозмездно эксплуатируют продукт | потеря дифференциации и revenue |
| B. BUSL 1.1 на весь репозиторий | сильная защита | закрывает runbook, отпугивает контрибьюторов, убивает публичный аргумент «open execution» | стратегический ущерб больше эффекта |
| C. **Двойная лицензия: MIT на docs/skills/tools, BUSL на engine** | защищает то, что продаётся, оставляет ценность открытой | нужна чёткая граница в репозитории и CI-проверка лицензии по путям | умеренная инженерия (§3) |
| D. Закрытый private core + public docs | максимум защиты | распад репозитория на два, сложнее вклад, дублирование | операционная цена |
| E. CLA вместо лицензии | гибко | требует юридического ревью договора, барьер входа | юридическая цена |

Выбран **C**.

## Решение

### 1. Распространение лицензий по путям

| Часть репозитория | Лицензия | Клаузула |
| --- | --- | --- |
| `career-intelligence-research-specs-v02/` (архив) | CC BY 4.0 | свободное использование с атрибуцией |
| `docs/` (документы, runbook, glossary, roadmap) | CC BY 4.0 | то же |
| `skills/`, `tools/`, `.github/`, CI | MIT | без дополнительных ограничений |
| `README*`, `CONTRIBUTING.md`, `LICENSE*` | MIT | без изменений |
| **будущий `engine/`**, policy packs, live recipes, verification runtime, ranking data | BUSL 1.1 | §2 |

BUSL действует только на версии, выпущенные после принятия настоящего ADR.
Коммиты до принятия остаются MIT / CC BY и не могут быть переведы задним
числом.

### 2. Условия BUSL 1.1

Draft параметров (финальные — владельцу до подписи):

- **Change Date**: через 4 года с даты каждого релиза, либо при первом
  выходе соответствующего стабильного релиза, что наступит позже;
  на Change Date версия конвертируется в Apache-2.0.
- **Additional Use Grant**: право на производство и внутреннее использование;
  запрещено предоставлять движок как hosted service / конкурирующий продукт
  без коммерческой лицензии.
- **Коммерческая лицензия**: предоставляется владельцем на условиях
  коммерческого договора (отдельная оферта).
- **Контрибьюторы**: каждый PR несёт `Signed-off-by` (DCO). PR без подписи
  не мержится. Контрибьютор, не согласный, пишет issue.

### 3. Граница в репозитории

- Появляется отдельный каталог `engine/` **когда** появится код движка.
  До тех пор BUSL применяется к будущему движку, а не к пустышкам.
- `LICENSE` остаётся MIT как общая, `LICENSE-BUSL.md` кладётся рядом при
  принятии ADR для файлов `engine/` (per-path лицензия).
- CI добавляет проверку: каждый файл в `engine/` несёт заголовок
  `SPDX-License-Identifier: BUSL-1.1`; отсутствие заголовка роняет сборку.
- `CONTRIBUTING.md` получает DCO-требование до первого внешнего PR.

### 4. Что не входит в это решение

- Переключатель видимости, цены, metering, контрактная оферта — отдельно
  (`MONETIZATION_STRATEGY.md`, §«Следующие решения»).
- Переписывание истории, отзыв MIT на существующем, ограничение форков —
  **прямо запрещено** этим ADR.

## Последствия

Проще: можно открыть продукт на GitHub и при этом продавать исполнение;
public argument сохраняется («see everything except the secret sauce»);
юридический объект (BUSL) — признанный индустрией инструмент.

Сложнее: два лицензионных режима → нужна дисциплина per-file SPDX;
контрибьюторский процесс дороже (DCO); часть аудитории MIT-«fanatics»
откажется от вклада сознательно; обязательны согласованные условия
с юристами до публичного заявления.

Влияние на security / privacy / legal:
- security: состояние не меняется; BUSL — лицензия, не контроль.
- privacy: не меняется.
- legal: **триггер legal review обязателен**: (1) текст BUSL и Change Date,
  (2) совместимость с исходной MIT-версией, (3) конвергенция с условиями
  архива 3rd-party (например, спецификации O*NET/ESCO с оговорками),
  (4) DCO vs CLA.

## Юридическая проверка

`TRIGGERED` — до подписи владельцем и до первого коммита под BUSL.

## Откат

- ADR отвергается: `engine/` не создаётся, `MONETIZATION_STRATEGY.md`
  пересматривается; все остаётся MIT.
- BUSL применён: отзыв только через новые версии; практическая необратимость
  как у любого публичного open-track релиза.
