# decisions — Architecture Decision Records

Любое изменение, затрагивающее контракты, лицензию или границы подсистем,
оформляется ADR. Шаблон — `docs/templates/ADR.md`.

## Правила

1. **Статус обязателен** в frontmatter: `PROPOSED`, `ACCEPTED`, `REJECTED`,
   `SUPERSEDED`.
2. **Отклонённый ADR не удаляется** — иначе решение будет обсуждаться заново.
3. **Один ADR — одно решение.** Не сваливать лицензию, стек и схему данных
   в один документ.
4. **Ссылка на ADR** обязательна в задаче или gate-отчёте, который это
   решение применяет.
5. **Нумерация не переиспользуется.** Отклонённый номер остаётся занятым.

## Кто принимает

| Тип решения | Кто подписывает |
| --- | --- |
| Контракты, схемы, границы подсистем | архитектор (IDE готовит) |
| Лицензия, цены, юрисдикция, пилот | владелец |
| Security / privacy / legal | владелец + counsel, где требуется |

Внутри IDE не принимается ни одно юридически значимое решение: создаётся
триггер на review, а не вывод.
