# PILOT_OPTIONS — кандидаты пилота для STAGE-00A

Это **вход для решения владельца**, а не решение. Пилот выбирает человек
(`docs/templates/PILOT_DECISION.md`). Здесь нет ни одного числа рынка:
любая цифра в этом документе была бы выдумкой, поэтому вместо чисел —
что именно нужно измерить и как дешево это сделать.

## Требования к пилоту (из архива)

- Одна профессия и **один узкий измеримый workflow** (`51_MISSING_LAYERS…`).
- Требуемый исход наблюдаем и проверяем (`44_MASTER_ROADMAP_P0_P2`).
- Достаточно данных для таксономии задач, иначе «AI applicability» нечем
  обосновать (`24_AI_TASK_MAPPING_SPEC`).
- Риск регулирования низкий, чтобы legal gate не остановил P0
  (`12_LEGAL_COMPLIANCE_SPEC`).
- Есть канал, где этих людей можно найти за разумные деньги
  (`18_GROWTH_MARKETING_SPEC`).

## Критерии сравнения

| Критерий | Почему важен |
| --- | --- |
| Измеримость исхода | без него P0 gate невозможен |
| Частота задачи | редкая задача не даёт повторяемости |
| Доступность данных о задачах | иначе applicability — догадка |
| Регуляторный риск | высокий риск = длинный legal gate |
| Цена привлечения | P0 должен быть дешёвым |
| Нужен ли LLM | если нет — P0 проще и дешевле |

## Вариант A. Малый бизнес в услугах: подготовка коммерческих предложений и смет

**Кто:** владелец или менеджер небольшой сервисной компании (электрика,
ремонт, монтаж, клининг), 1–20 человек.

**Workflow:** запрос клиента → уточнение деталей → черновик сметы/КП →
проверка человеком → отправка → фиксация фактических затрат.

**Почему это хороший P0:**
- Задача частая, повторяемая, с наблюдаемым исходом (время до ответа клиенту,
  конверсия в заказ, расхождение сметы и факта).
- Архив уже содержит разобранный пример именно этого процесса
  (`25_AI_WORKFLOW_SPEC.md`, раздел «Example: service request to estimate»).
- Регуляторный риск низкий.
- `NON_AI`-решение (шаблон + чек-лист) существует и должно честно
  конкурировать с AI-вариантом — это проверяет главный принцип продукта.

**Что неизвестно и требует измерения:**
- Сколько таких компаний доступно в выбранном городе/стране.
- Готовы ли они платить и сколько.
- Есть ли у них цифровые данные (старые сметы) для проверки качества.

**Чем проверить дешево:** 5–8 интервью, вручную подготовить 3 сметы по
реальным запросам, сравнить с тем, что сделал бы владелец. Никакого кода.

**Нужен ли LLM:** вероятно да, для черновика по свободному тексту запроса.
Но P0 может стартовать с шаблона и чек-листа (`NON_AI`) и добавить LLM
по итогам STAGE-05A.

## Вариант B. Карьерный переход в IT для людей вне IT

**Кто:** человек 25–40 лет с опытом в другой сфере, рассматривающий переход
в аналитику/тестирование/поддержку.

**Workflow:** текущий опыт → переносимые навыки → конкретная целевая роль →
разрыв → один учебный шаг → доказательство навыка (pet-проект) → отклик.

**Плюсы:** огромный спрос, много публичных данных, понятная таксономия,
сильный SEO-канал. Исход измерим (создан артефакт, отправлена заявка,
получен ответ).

**Минусы:** рынок перегрет конкурентами (`02_COMPETITOR_RESEARCH`,
`22_RESEARCH_CRITIQUE`), высокая цена привлечения, слабая готовность платить,
исход растянут во времени — плохо для 14-дневного окна измерения.

**Что неизвестно:** готовность платить, реальная конверсия «совет → действие».

**Чем проверить:** 10 интервью + один ручной «путь» для 3 человек.

## Вариант C. B2B2C через учебный центр или центр карьеры

**Кто:** университетский карьерный центр или небольшой учебный центр,
который ведёт группу людей.

**Workflow:** диагностика группы → приоритизированный список задач и
навыков → внедрение одного изменения → измерение результата на группе.

**Плюсы:** ниже CAC, платит организация, есть готовый канал
(`16_B2B2C_AND_PARTNER_VALUE_SPEC`), исход измеряется на группе.

**Минусы:** длинный цикл продажи и procurement, P0 растягивается по времени;
риск, что продукт начнут требовать «как enterprise» до доказательства ценности.

**Что неизвестно:** цикл сделки, кто реально подписывает, какой результат
они считают доказательством.

**Чем проверить:** 3 встречи с руководителями центров, один бесплатный
пилот на 10 человек с ручной работой.

## Рекомендация (не решение)

Если цель — **быстро доказать цикл за минимальные деньги**, вариант A даёт
самый короткий путь к наблюдаемому исходу и допускает `NON_AI`-старт.
Вариант B — самый большой рынок, но худший для 14-дневного окна проверки.
Вариант C — лучший CAC, но худший срок до gate.

## Что нужно от владельца (заполняется в PILOT_DECISION.md)

1. ICP и профессия.
2. Один workflow.
3. Страна / юрисдикция.
4. Baseline и целевой исход + кто его подтверждает.
5. Пороги P0 gate (числа).
6. Бюджет и срок.
7. Таксономия: O*NET / ESCO / местная / гибрид.
8. Стек (или «на усмотрение ADR-0002»).
